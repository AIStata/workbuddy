Task 5｜专家与团队（Expert Team）

团队协作

5.1 什么是专家（Expert）

专家用于为 WorkBuddy 配置专业角色，在特定领域中以更明确的方法和视角完成任务。官方给出两句关键定性：

  • 专家是「角色切换」机制：以“人设 + 方法论 + 工具链”让 WorkBuddy 用特定领域专家身份执行任务。
  • 专家团是「协作执行」机制：由多位专家分工，由团长自动拆解、并行执行、整合交付。
维度 Skill 专家（Agent 型） 专家团（Team 型）
本质 工具能力：让 AI 能做某件事 AI 顾问：懂某领域的角色 AI 协作团队：拆解、并行、完整交付
怎么选 需要某种工具能力 有一个明确的单点问题 任务复杂，需多角色配合

使用步骤：侧边栏「专家·技能·连接器」默认「专家」页签 → 浏览卡片（专家展示能力介绍、擅长领域、任务示例；专家团额外展示团队成员）→ 点「召唤」进入对话 → 描述任务。召唤后会随机选一条引导提示词作为开场。

注意

积分提示：专家团积分消耗通常为单专家的 3–5 倍（并行调用多位专家、多轮交互），召唤前请关注余额。依赖 MCP/连接器的专家在未连接时会显示引导卡片，授权后自动继续当前任务。

5.2 设计你的专家团队

在客户端创建专家

  1. 「专家」页右上角点「我的专家」。
  2. 点「创建专家」，系统进入创建对话，由内置专家管理工具引导配置（无需额外安装）。
  3. 按对话提示配置，完成后出现在「我的专家」列表，选中即可召唤。
配置项 建议做法 应避免
头像与名称 短角色名，如“文档评审官” “专家1”“助手”等无指向名称
人设身份 “是谁 + 有什么背景”，如“10 年经验的后端工程师” 写成任务本身
擅长领域 写清“做什么 / 不做什么” “什么都行”
提示词 写工作流程、输出格式与约束，能举例最好 只写“您是一个专家”
注意

官方提示：创建前请确认名称，创建后无法修改，改名需重新创建。管理入口在「我的专家」卡片「⋯」：修改、分享（对方获得副本）、删除。

专家包结构（上架市场用）

my-expert/
├── .codebuddy-plugin/
│   └── plugin.json
├── avatars/
│   └── expert.png
├── agents/
│   └── my-expert.md
└── README.md

plugin.json 关键字段：name（唯一标识）、expertType（agent 或 team）、agentName、团队用 teamInfo{leadAgent, memberAgents}、displayName/profession/displayDescription（中文字数 40–50）、defaultInitPrompt、quickPrompts（3 个）等。Agent 定义文件为 Markdown，文件头用 YAML frontmatter 声明 name/description/displayName/profession，正文为系统提示词。

说明

官方明确：开发者不可自行添加 tools，所有工具权限由系统统一分配。内置工具包括 Read、Write、Grep、Glob、Bash、WebSearch、WebFetch，以及主理人可用的 AgentTool（调用其他 Agent）与 SendMessage。

5.3 子 Agent

用户常说的“子 Agent”，在 WorkBuddy 官方体系中主要对应两种形态：

  • 专家团中的成员 Agent：由 teamInfo.leadAgent（主理人/团长）与 teamInfo.memberAgents（成员列表）构成，团长通过 AgentTool、SendMessage 调度成员。
  • 通过 AgentTool 调用的其他 Agent：主理人可调用其他 Agent 协作完成任务。

调用方式对用户极简：召唤专家团后用自然语言描述任务，团长自动拆解、分配、执行并返回完整结果。配置则通过专家包的 teamInfo 与 agents/ 目录下的 Agent 定义文件（Markdown + YAML frontmatter）声明。

说明

易混淆点：侧边栏的「助理（远程任务）」是用手机远程控制电脑上的 WorkBuddy，与子 Agent / 多 Agent 协作无关，只是命名相近。公开的客户端文档未设独立的“子 Agent 配置界面”说明。

在客户端内部实现中，主 Agent 可把任务委派给不同类型的子代理（例如通用型 general-purpose 用于多步骤调研与执行、探索型 Explore 用于快速检索代码与资料、以及表格/文档等专用代理），并支持多代理团队协作与消息互通。这类内部类型由系统提供，用户主要通过专家团与专家配置来间接使用。

5.4 专家 vs 子 Agent

专家（Expert / Agent 型）

角色切换机制：单一 AI 角色，用特定领域的人设、方法论、工具链解决一个明确的单点问题。

积分消耗相对低；配置以人设 + 提示词为主。

子 Agent / 专家团（Team 型）

协作执行机制：多角色分工，团长自动拆解、并行执行、整合交付，用于复杂、需多角色配合的任务。

积分约为单专家 3–5 倍；通过 teamInfo 与 Agent 定义文件配置。

提示

怎么选：需要工具能力 → Skill；有明确单点问题 → 专家；任务复杂需多角色配合 → 专家团（多子 Agent 协作）。
